# Sight Cache image worker

This Worker samples camera frames from R2, builds contact sheets with Cloudflare Images, and exposes read-only camera tools over MCP.

## MCP tools

| Tool | Behavior |
| --- | --- |
| `list_devices` | Lists active devices and their latest upload time. |
| `get_contact_sheet` | Returns one JPEG group plus timestamp metadata for a completed minute or hour. |
| `list_frames` | Lists exact capture timestamps in a suspicious interval of up to five minutes. |
| `get_original_frame` | Returns the untouched JPEG uploaded at an exact `capturedAt` timestamp. |

Hourly windows are generated by the `5 * * * *` cron and split into six groups. Each group contains ten samples at one-minute intervals in a 2-by-5 row-major grid.

Minute windows are generated on the first request, cached in R2, and split into two groups. Each group contains six samples at five-second intervals in a 2-by-3 row-major grid. A minute is not finalized until five minutes after it ends so delayed uploads are not cached as missing.

All stored keys and returned timestamps use UTC. Inputs may contain another ISO 8601 offset, but hourly windows must resolve to a UTC hour boundary.

## Authentication

Protect the Worker's `/mcp` endpoint with a Cloudflare Access application and enable Access Managed OAuth for the MCP client. Cloudflare performs the OAuth flow at the edge; this Worker does not implement authorization, token, registration, or protected-resource metadata endpoints.

The OAuth bearer token sent by the MCP client is opaque. After Access accepts it, Access adds a signed `Cf-Access-Jwt-Assertion` header to the origin request. The Worker validates that assertion against the Access application audience and the team domain's JWKS before running an MCP request.

Set these Worker variables or local values in `.dev.vars`:

```dotenv
ACCESS_TEAM_DOMAIN=https://your-team.cloudflareaccess.com
ACCESS_AUD=your-access-application-aud
MCP_ALLOWED_ORIGIN_HOSTNAMES=chatgpt.com
MCP_MAX_LOOKBACK_DAYS=7
```

`ACCESS_AUD` is the AUD tag shown for the Access application. `ACCESS_TEAM_DOMAIN` is the team's `https://<team>.cloudflareaccess.com` domain. The assertion must have:

- an `iss` matching `ACCESS_TEAM_DOMAIN`
- an `aud` containing `ACCESS_AUD`
- a valid `exp` and `sub`
- an RS256 signature verifiable at `/cdn-cgi/access/certs`

Keep `workers_dev` disabled and do not expose another route that bypasses the Access application. Because this Worker uses a Static Assets binding, it validates `Cf-Access-Jwt-Assertion` directly instead of relying on `ctx.access`, which is not forwarded through the internal assets router.

`MCP_MAX_LOOKBACK_DAYS` limits both generated contact sheets and original-frame reads to a bounded history. It defaults to 7 and accepts values from 1 through 365.

`chatgpt.com`, `chat.openai.com`, and loopback hosts are allowed as browser Origins by default. Add comma-separated hostnames with `MCP_ALLOWED_ORIGIN_HOSTNAMES` when another trusted MCP client requires browser access.

The MCP endpoint is `/mcp`. Managed OAuth serves its OAuth discovery and challenge responses at the Cloudflare Access edge, before requests reach this Worker.

The collector's `scd_...` upload token is intentionally not accepted for image reads.

Every principal allowed by the Access application can currently read every active device. Restrict the Access policy to the owner; add identity-to-device grants before using this Worker as a multi-user service.

## Commands

```sh
npm install
npm run typecheck
npm run dev
npm run mcp-inspect
npm run deploy
```

Regenerate Cloudflare binding types after changing `wrangler.jsonc`:

```sh
npm run cf-typegen
```
