開源影像記憶

給 Agent 現場脈絡，不必搬走整段串流。

Sight Cache 將 RTSP 監視器歷史整理成精簡的縮圖總覽，再讓 AI Agent 透過受保護的唯讀 MCP 工具，只檢視真正需要的精確畫面。

開始設定 Sight Cache 跟著影格走一遍 ↓

自行部署於你的 Cloudflare 帳號

  • 5 秒原始影格的預設擷取間隔
  • 60 格每個完整小時的一分鐘取樣數
  • 4 項工具從總覽走到證據的唯讀 MCP 流程

從攝影機到脈絡

保留證據，減少逐格尋找。

Agent 先看精簡的小時總覽，再縮小到可疑的分鐘區間；只有在能補足證據時，才讀取原始影格。

  1. 01

    在攝影機附近擷取

    Node.js Collector 使用 FFmpeg 暫存帶有時間戳的 JPEG，再依序上傳。

  2. 02

    在邊緣儲存原始畫面

    Ingest Worker 驗證設備與影像內容，再將原始畫面寫入 R2。

  3. 03

    整理已完成的時間區間

    排程 Queue 建立每小時總覽；短分鐘總覽則只在真正查詢時建立。

  4. 04

    透過 MCP 檢視

    Image Worker 提供由 Cloudflare Access OAuth 保護、無狀態且唯讀的檢視路徑。

四項唯讀工具

從總覽一路找到精確證據。

檢視步驟保持明確：列出設備、掃過縮圖總覽、找到鄰近時間戳，最後只開啟重要的原始畫面。

  • list_devices找出啟用中的攝影機
  • get_contact_sheet檢視一分鐘或一小時
  • list_frames找出精確拍攝時間
  • get_original_frame取得未修改的原始證據

小而分工清楚的系統

每個服務只負責一件明確的事。

擷取留在攝影機附近，儲存與處理交給 Cloudflare，而檢視流程始終由你的 Access policy 保護。

攝影機端

輕量 Collector 擷取 RTSP 影格，不必持續將完整視訊串流送上雲端。

  • Node.js
  • FFmpeg
  • Docker

Cloudflare 上

三個 Worker 負責驗證、儲存、整理、排程，以及提供影像歷史。

  • Workers
  • D1
  • R2
  • Images
  • Queues

Agent 端

任何相容的 MCP Client 都能經由無狀態 endpoint 檢視已授權的歷史。

  • MCP
  • Managed OAuth
  • 唯讀

謹慎處理私人畫面

保護機制是管線的一部分。

Sight Cache 提供必要控制；Cloudflare 帳號、Access policy、儲存生命週期，以及每組攝影機憑證仍由你掌握。

  • 保護管理與 MCP 路由：分別設定相符的 Cloudflare Access Application。
  • 只儲存 Token 雜湊：完整 Collector Token 僅在核發時顯示一次。
  • 設定 R2 lifecycle rule：讓影像保留時間符合你的實際需求。

讓第一台攝影機上線

從 repository 與明確的保留政策開始。

建立 Cloudflare 資源、部署三個 Worker，再於每台 RTSP 攝影機附近執行一個 Collector。文件已列出所有 binding 與環境變數。

  • Node.js 24.19+
  • FFmpeg 或 Docker
  • Cloudflare Workers Paid
